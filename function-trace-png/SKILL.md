# Function Trace PNG Skill

把一个函数的调用链梳理成**带注解的调用图**，**渲染成 PNG 图片**交付。

本 skill 是 `function-trace-diagram` 的「图片版 + 带'为什么'注解版」。**方法论继承它**（三层配色、先查源码、自检清单）；若只要终端 ANSI 图，直接用 `function-trace-diagram`，别用本 skill。本 skill 相对它有三处强化：

1. **出 PNG**：走 HTML → headless Edge/Chrome → 图片文件，而不是终端 ANSI。
2. **每个检查都写"为什么"**（本 skill 最强调，最容易漏）。
3. **拆成多张图**：一张概览 + 每个分支一张详细图。

## 何时用

- 用户要**图片格式**（PNG/给同事看/贴文档）的调用图。
- 用户抱怨"光有函数名看不懂"——需要**解释动机**的图。
- 一个函数有**多条分支**（如匿名/文件、快路径/慢路径），需要分开讲清。

## 铁律

1. **先查源码再画。** 所有函数名、行号必须 `Grep`/`Read` 确认，严禁凭记忆（曾把 `scheduler_tick` 记成 `sched_tick`）。输出前核对。
2. **每个检查写"为什么"。** 凡是 `if`/阈值/`goto fail`/失败码，除了写"是什么/触发条件"，**必须**补一句动机：为什么做这个检查、不做会怎样。
   - ❌ `空页超 max_ptes_none → 失败`
   - ✅ `空页超 max_ptes_none → 失败　// 为什么：大页是整块分配的，空页越多=这段越稀疏，合并会为没用到的虚地址占内存，故限比例(默认511)`
3. **函数名必须上色**，颜色分层（见下）。

## 配色（三层 + 辅助）

| 层 | 标记 | 颜色 | 用在哪 |
|---|---|---|---|
| 框架/承接 | `[[C]]` | 青 | 更上层框架入口；或"承接上一张图"的虚根 |
| **核心入口** | `[[B]]` | 蓝 | **本张图的根函数**（每张图自己的入口） |
| **骨干函数** | `[[Y]]` | 黄 | 链路上最关键的几个节点 |
| **叶子子函数** | `[[P]]` | 紫 | 其余辅助调用 |
| 分配/创建 | `[[G]]` | 绿 | `alloc_*`/`kzalloc`/`*_init` |
| 关键变量/锁 | `[[W]]` | 白 | 重要变量、锁、标志 |
| 关键转折/失败 | `[[R]]` | 红 | `★` 标的关键跳转、`SCAN_*` 失败 |
| 注释与"为什么" | `[[D]]` | 灰 | 行号、解释、动机 |

## 多图结构（默认出多张）

- **概览图**：只画"入口 → 分叉点"，分叉处标 `→ 见图《X》`。2~4 层。
- **每分支详细图**：根 = 该分支入口，追到关键子函数，每处检查带"为什么"。

例（khugepaged）：`collapse_scan_mm_slot` 概览 → 分叉出《匿名页路径》《文件页路径》两张详细图。

## 工作流

1. **定范围**：从哪个入口开始？分几条路径？要几层？
2. **查源码**（必做）：`Grep`/`Read` 确认所有被调函数名 + 行号 + **每个检查的动机**（读函数注释、`Documentation/`）。
3. **写树文本**：用 `[[X]]` 标记，每处检查后跟"为什么"（写成文件，见语法）。
4. **渲染**：`python scripts/make_diagram.py <tree.txt>` —— 生成 HTML + PNG，并打印尺寸。
5. **自检**：把导出的 PNG **读回来看一眼**，确认 ① 没被裁切 ② 颜色没漏到下一行 ③ 每个检查都有"为什么"。

## 树文本语法

文件用 `@@@` 分段，每段一张图：

```
@@@ 输出文件名 | 图的标题 | 副标题(可空)
khugepaged_do_scan(cc)                       [[D]]// khugepaged.c:2971[[/]]
  └─ [[B]]collapse_scan_mm_slot(cc)[[/]]      [[D]]// :2841 核心入口[[/]]
       ├─ [[P]]mmap_read_trylock(mm)[[/]]    [[D]]// 拿 mm->mmap_lock 读锁[[/]]
       └─ [[Y]]collapse_single_pmd(...)[[/]]
            [[D]]为什么查 X：……[[/]]
```

- 标记：`[[C]][[B]][[Y]][[P]][[G]][[W]][[R]][[D]]` 开色，`[[/]]` 闭合。
- **每行没闭合脚本会自动补**，所以颜色不会漏到下一行；但仍要自检。
- 行内不要嵌 `[[X]]`，用 `] [[X]]` 分段（如 `正文[[/]] [[P]]func()[[/]]`），保持括号配对。
- 标题/副标题是**纯文本**，不要放 `[[X]]` 标记（脚本只解析树体）。
- `<` `>` `&` 不用转义，脚本会处理。

## 渲染机制

- HTML（深色底 + `<pre>` + 着色 `<span>`）→ headless Edge/Chrome 截图 → PNG。
- **为什么不用 PIL/ImageMagick/cairo**：多数 Windows 机器没装（实测本机只有 Edge）；Edge 系统自带，最稳。
- 默认 `--scale 2`（2× 高清）；脚本按内容行数/最长行自动算窗口尺寸。
- 脚本自动找 Edge/Chrome；都没有则只出 HTML 并提示。

## 自检清单（输出前逐条过）

1. 所有函数名/行号都 `Grep`/`Read` 查过了？
2. **每个检查/失败分支都有"为什么"**？（本 skill 最易漏，重点查）
3. 函数名都上色了？分叉点是否指到了对应详细图？
4. PNG 读回确认：没裁切、没漏色。

## 反例（禁止）

- 脑补函数名/行号 → 必须查源码。
- **只写"是什么"，不写"为什么"** → 本 skill 最强调的一条。
- 把多分支塞进一张图导致又乱又长 → 拆成概览 + 每分支一张。
- 用 `\033` 字符串当颜色 → 那是 `function-trace-diagram`(ANSI 版)的事；本 skill 用 `[[X]]` 标记出图片。

## 用法示例

见 `templates/example_tree.txt`，直接：

```
python scripts/make_diagram.py templates/example_tree.txt --outdir ./out
```
